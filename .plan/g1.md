### Estratégia de Validação de Rotas (API)

Utilizaremos o **Pydantic v2** ou decoradores customizados no Flask para garantir que qualquer *Bad Request* (HTTP 400) seja interceptado antes de tocar na camada de cálculo. Se o frontend enviar uma string no lugar da coordenada ou uma frequência fora de 915–928 MHz, o backend rejeita imediatamente.

## 2. Vertente 1: O Sandbox de Antena Única

Esta aplicação será um laboratório virtual estruturado em POO (Programação Orientada a Objetos) no Python 3.13. Cada antena herdará de uma classe base.

### Parâmetros de Entrada por Tipo de Antena

* **Dipolo / Monopolo:** Comprimento dos braços ($\lambda/2$ ou $\lambda/4$), diâmetro do condutor, corrente de entrada, tensão e frequência.
* **Helicoidal:** Número de espiras, passo da hélice, diâmetro da espira e do plano de terra.
* **Parabólica:** Diâmetro do refletor, eficiência de iluminação e ganho do alimentador (*feed*).

### Métodos Numéricos de Simulação (O que usar?)

Como você mencionou a necessidade de simulações precisas além das fórmulas algébricas:

1. **Método dos Momentos (MoM):** É a escolha perfeita para **Dipolo, Monopolo e Helicoidal**. Ele discretiza a estrutura da antena em pequenos segmentos de fios e resolve as equações integrais de campo elétrico. No Python, podemos integrar a biblioteca `PyNEC` (baseada no tradicional NEC-2 de código aberto) para calcular a impedância de entrada, SWR (Relação de Onda Estacionária) e o diagrama de irradiação 3D exato.
2. **Óptica Física (PO) / Aproximação de Abertura:** Para a **Parabólica**, o MoM se torna pesado demais (exige muita memória se a antena for grande em relação ao comprimento de onda). Usamos aproximação de abertura para calcular o ganho diretivo e os lóbulos secundários.

## 3. Vertente 2: Planejamento Detalhado do Enlace LoRa (Os 10 Nós)

Analisando as coordenadas fornecidas (que apontam para a região do Campus Darcy Ribeiro da UnB, em Brasília), temos um cenário suburbano/urbano plano com variações de relevo e vegetação.

### Aprofundamento do Algoritmo: Ray Tracing vs. Modelos Empíricos

Você mencionou **Ray Tracing**. No contexto de propagação, o *Ray Tracing* (Traçado de Raios) modela as ondas de rádio como raios ópticos que sofrem reflexão em prédios, difração em arestas (telhados) e transmissão pelas paredes.

* **Viabilidade:** Ele é excelente, mas exige um modelo 3D digital exato do terreno e dos prédios (arquivos de shapefiles ou nuvens de pontos).
* **Recomendação Sênior:** Para o seu caso, onde o foco é a viabilidade do enlace a partir do KML (que dá a altitude do relevo), o algoritmo ideal para compor o backend é o **Modelo Longley-Rice (ITM - Irregular Terrain Model)** ou o **Modelo ITU-R P.526** (difração sobre terreno irregular). Eles calculam as perdas por obstrução do relevo (gume de faca) usando a altitude do arquivo KML. Se quiser incluir efeito predial sem modelagem 3D, usamos **Okumura-Hata** ou **3GPP UMa/UMi** adaptados para a frequência LoRa.

### A Dinâmica do Gateway (Centralizador) e das Setoriais

A sua ideia de ter o Gateway (Ponto Central) com múltiplas antenas apontadas para cada nó é excelente e mimetiza uma **Estação Rádio Base (ERB) Profissional**.

Como as antenas parabólicas possuem uma diretividade altíssima (feixe muito estreito, de poucos graus), uma única parabólica fixa não conseguiria ouvir todos os 10 nós espalhados pelas coordenadas. Temos duas abordagens de design para implementar na tela de configuração da aplicação:

1. **Abordagem Omnidirecional/Helicoidal no GW:** O Gateway usa uma antena Helicoidal em modo axial (ou monopolo de alto ganho) que irradia em 360°. Os nós periféricos usam antenas direcionais (como uma Yagi ou mini-parabólica) apontadas cirurgicamente para a coordenada do Gateway.
2. **Abordagem de Arranjo Setorial (Sua sugestão):** O Gateway possui um *cluster* de antenas. O script Python varre os 10 pontos, calcula o azimute ($\theta$) e a elevação ($\phi$) de cada nó em relação ao Gateway escolhido e projeta o ângulo exato que cada antena do Gateway precisaria ter.

### Matriz de Viabilidade Técnica (O Core da Aplicação)

Para cada enlace (Nó $i \rightarrow$ Gateway), o motor em Python 3.13 computará o **Orçamento de Link (Link Budget)** através da fórmula:

$$P_{RX} = P_{TX} + G_{TX} - L_{TX} - L_{FS} - L_{M} - L_{obst} + G_{RX} - L_{RX}$$

Onde:

* $P_{RX}$: Potência recebida no destino (dBm).
* $P_{TX}$: Potência de transmissão do rádio LoRa (tipicamente de +14 dBm a +20 dBm de acordo com os limites da ANATEL).
* $G_{TX} / G_{RX}$: Ganhos das antenas calculados na Vertente 1 (dBi).
* $L_{FS}$: Perda de Espaço Livre ($20\log_{10}(d) + 20\log_{10}(f) + 32.44$).
* $L_{obst}$: Perda por obstrução do terreno extraída do perfil de altitude do KML.
* **Critério de Sucesso:** $P_{RX} > \text{Sensibilidade do Receptor LoRa}$ (geralmente por volta de -137 dBm a -148 dBm, dependendo do Spreading Factor - SF utilizado).

O sistema gerará na interface uma tabela HTML limpa e um mapa dinâmico colorindo os enlaces: **Verde** (Margem de link segura > 20 dB), **Amarelo** (Margem limítrofe entre 10 e 20 dB) e **Vermelho** (Enlace inviável/obstruído).

## 4. Próximos Passos para o Desenvolvimento

Para tirarmos esse projeto do papel de forma iterativa, sugiro dividirmos o roadmap nas seguintes fases:

1. **Sprint 1 (Backend Core - Vertente 1):** Escrever as classes em Python 3.13 das 4 antenas e criar o endpoint Flask `/api/v1/sandbox/simulate` que retorna o ganho e o diagrama de irradiação em JSON para o frontend plotar via JavaScript (usando uma biblioteca leve como `Chart.js` ou `Plotly.js`).
2. **Sprint 2 (Frontend Interface - Vertente 1):** Construir a página HTML/CSS pura do Sandbox, validando os inputs do usuário e exibindo as curvas de ganho.
3. **Sprint 3 (Parser KML e Elevação - Vertente 2):** Implementar a lógica de leitura do arquivo `.kml` (usando a biblioteca `fastkml` ou `BeautifulSoup`) para extrair Latitude, Longitude e Altitude dos pontos informados no Matlab.
4. **Sprint 4 (Motor de Enlace e Matriz de Decisão):** Implementar o algoritmo de cálculo de perda de propagação (Longley-Rice ou similar) e a lógica de seleção automática de qual dos pontos performa melhor como o Gateway da rede.
